2️⃣ Request OTP

POST
/sms/request-otp Endpoint path

Triggers generation of a stateless, cryptographic OTP transaction. Locks identity channels and delivers the code using the configured Notification Dashboard.

📌 Parameter Specifications

Field Requirement Description
user_name String (Required) Target user logging in or transferring funds
mobileNumber String (Optional) 10-digit Indian Mobile Number matching ^[6-9]\d{9}$
email String (Optional) Target verification email address
Identity Rule Constraint At least one of mobileNumber or email must be provided.
params String (Required) Unique transaction ID (10 to 150 characters) to prevent duplicate submission
bankCode String (Optional) Bank Code identifier. Determines expiration (IDBI = 5min, SBI = 3min, Default = 2min)
messageData Object (Required) Meta payload containing parameters injected during notification delivery
status String (Optional) Transaction status code override
📥 View Request Body Payload Example 
{
  "user_name": "john_doe",
  "mobileNumber": "9876543210",
  "email": "john_doe@example.com",
  "params": "txn123456abcd",
  "bankCode": "IDBI",
  "feature": "LOGIN",
  "operationPerformed": "OTP_VERIFICATION",
  "messageData": {
    "template": "otp_sms"
  },
  "status": "SUCCESS"
}

3️⃣ Resend OTP

POST
/sms/resend-otp Endpoint path

Re-generates and resends the OTP by verifying the original requestToken. The validity timer is automatically reset and a updated token is returned.

📥 View Request Body Payload Example 
{
  "requestToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6Ijk4NzY1NDMyMTA...",
  "email": "john_doe_new@example.com",
  "status": "SUCCESS",
  "messageData": {
    "template": "otp_sms"
  }
}
🟢 Success Response (New Token Generated) 
{
  "status": 0,
  "success": true,
  "displayMessage": "OTP resent successfully (Dev mode: 482910 is your OTP)",
  "requestToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6Ijk4NzY1NDMyMTA..."
}

4️⃣ Validate OTP

POST
/sms/validate-otp Endpoint path

Validates the user-submitted OTP code against the TOTP secret key cryptographically embedded inside the requestToken. On success, issues a signed verification proof session token.

📥 View Request Body Payload Example 
{
  "requestToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6Ijk4NzY1NDMyMTA...",
  "otp": "482910"
}

🧪 Step-by-Step Integration Testing Runbook

💡
Chaining Collection Variables
If using the downloadable Postman collection, the test scripts automatically extract and chain the requestToken, otp, and sessionToken variables, allowing you to run the flow sequentially with one click!
  1. Check Heartbeat

    Verify server is alive: GET /HbtChk. Expect status "UP".

  2. Generate OTP & Token (Request OTP)

    POST to /sms/request-otp with valid identity parameters. Extract the requestToken and otp from the response message.

  3. Test Duplicate Rate Locking

    Immediately re-submit Step 2 request. Expect 400 Bad Request with duplicate locks message.

  4. Test Expiry Timer Refresh (Resend OTP)

    POST to /sms/resend-otp using the requestToken from Step 2. Verify you receive a fresh requestToken and the timer resets.

  5. Verify Code Authentication (Validate OTP)

    POST to /sms/validate-otp with the new requestToken and otp (or use dev bypass 000000). You will receive the signed sessionToken.

  6. Test Replay Attack Rejection

    Submit the validation call again with the same parameters. Expect a 400 error stating the token has already been consumed.

  7. Verify Cryptographic Proof (Verify Session)

    POST to /sms/verify-session using the sessionToken. Check that all fields inside data match your original request fields.
